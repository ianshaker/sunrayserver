# Справочник городов

Единый источник названий и координат городов для всего сервера.

## Откуда данные

Таблица `cities` в Supabase — та же, которую читает CRM. Города заводит менеджер
сам: в CRM, в поле выбора города, есть строка «Не нашли город? Добавить новый».
Оттуда приходят название, координаты и куст Подмосковья.

Списков городов в коде больше нет. Единственное исключение — `fallback.js`: копия
на случай, когда база не ответила. Она не обновляется руками и намеренно может
отставать.

## Как пользоваться

```js
const cities = require("../cities");

const resolved = await cities.resolveCity("в Можайске");
// { raw: "в Можайске", canonical: "Можайск", found: true }

const ok = await cities.hasCoordinates("МСК-Юго-Запад");    // false

// Расстояния: справочник берётся один раз, дальше счёт без ожиданий.
const index = await cities.citiesByName();
const km = cities.distanceBetweenCities(index, "Дубна", "Клин");   // 43.6
```

Наружу модуль отдаёт ровно эти четыре вещи. Всё остальное — внутренняя кухня.

## Кэш

Справочник читается из базы раз в десять минут и держится в памяти процесса.
Меняется он от силы раз в неделю, а бот расписания отвечает десятки раз в час.
Параллельные обращения ждут один запрос, а не шлют свои.

Если база не ответила — в лог уходит строка `[cities] справочник из базы не
прочитан … работаем на резерве`, и запрос обслуживается последним удачным списком,
а при его отсутствии — резервом. Отказ тоже запоминается на те же десять минут:
в упавшую базу не стучимся каждым вопросом. Бот должен ответить даже со старым
списком: молчание хуже неточности.

## Что где лежит

| Файл | Что в нём |
|---|---|
| `index.js` | единственный вход: список, резолюция имени, расстояния |
| `store.js` | чтение из базы, кэш, переход на резерв |
| `matching.js` | написание без ё, падежи, опечатки |
| `geo.js` | расстояние по прямой (Хаверсин) |
| `fallback.js` | резерв: 131 название и 127 пар координат на 13.09.2026 |

## Двойник в CRM

Те же правила сравнения названий продублированы в
`sunray-crm-oasis/src/utils/cityMatching.ts` — там они нужны в браузере, до записи
города в базу. Меняешь правило здесь — поменяй и там, иначе окно добавления и
сервер начнут по-разному понимать «Королев» и «Королёв».

## История

До 13.09.2026 список жил в `schedule-ai/cityAliases.js`, координаты — в
`schedule-ai/cityCoordinates.js`, и обе копии синхронизировались руками с CRM.
Оба файла удалены, их данные лежат в `fallback.js`.
